## 1. Общий обзор стека

| Уровень | Технология | Назначение |
| :--- | :--- | :--- |
| **Backend** | Python 3.11+ / Go | Бизнес-логика и вычислительные алгоритмы |
| **Frontend** | React + TypeScript | Пользовательский интерфейс (Mobile-First) |
| **Database** | PostgreSQL 15 | Основное реляционное хранилище |
| **Cache** | Redis | Хранение сессий и кэширование расписания |
| **Infrastructure** | Docker & Docker Compose | Контейнеризация сервисов |

## 2. Backend технологии

### Языки и Фреймворки
* **Python (FastAPI):** Основной язык для реализации модуля генерации расписания.
    * *Обоснование:* Наличие мощных библиотек для работы с данными и математической оптимизации (NumPy, SciPy), необходимых для работы «Пчелиного алгоритма».
* **Go (Golang):** Используется для высоконагруженных сервисов уведомлений и API-шлюза.
    * *Обоснование:* Высокая скорость работы и эффективное управление конкурентными запросами.

### Инструменты разработки
* **SQLAlchemy / GORM:** Для типобезопасной работы с базой данных и автоматической миграции схем.
* **Pydantic:** Для строгой валидации входящих данных в API.

---

## 3. Frontend технологии

### Ядро и Состояние
* **React:** Библиотека для создания динамических интерфейсов. Позволяет эффективно отрисовывать сложную сетку расписания.
* **TypeScript:** Обеспечивает статическую типизацию, снижая количество ошибок при передаче данных между фронтендом и бэкендом.
* **Zustand:** Легковесный менеджер состояний для управления фильтрами и пользовательскими настройками в реальном времени.

### Стилизация
* **Tailwind CSS:** Утилитарный CSS-фреймворк для реализации адаптивного дизайна под мобильные устройства студентов.

---

## 4. Интеграции и Сообщения

* **RabbitMQ:** Брокер сообщений для асинхронного взаимодействия. Используется для уведомления внешних систем (например, Telegram-бота) об изменениях в расписании.
* **OpenAPI (Swagger):** Для автоматической генерации документации API и контрактов взаимодействия.

---

## 5. Инфраструктура и DevOps

* **Docker:** Позволяет изолировать зависимости каждого микросервиса и гарантирует идентичность окружения на компьютерах разных разработчиков.
* **GitHub Actions:** Настроен пайплайн CI/CD для автоматического прохождения тестов при каждом Pull Request и деплоя документации на GitHub Pages.
* **Docusaurus:** Движок для создания данного портала документации по принципу "Docs as Code".
