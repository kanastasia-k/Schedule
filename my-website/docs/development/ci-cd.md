## 1. Общий обзор процесса (Workflow)
*Краткое описание того, как push в ветку `main` или создание Pull Request запускает цепочку автоматизаций (GitHub Actions).*

## 2. Continuous Integration (CI)
Здесь описываются проверки, которые проходит код перед слиянием:
* **Linting:** Проверка стиля кода (ESLint для TS, Flake8/Ruff для Python).
* **Unit Testing:** Запуск модульных тестов для Backend и Frontend.
* **Security Scan:** Поиск секретов в коде и уязвимостей в зависимостях.
* **Build Check:** Пробная сборка Docker-образов, чтобы убедиться, что проект «собирается».

## 3. Сборка и хранение артефактов
* Описание процесса сборки Docker-образов.
* Указание реестра (например, GitHub Container Registry), где хранятся готовые образы сервисов.

## 4. Continuous Deployment (CD)
Описание процесса доставки кода в разные среды:
* **Staging:** Автоматический деплой веток для тестирования.
* **Production:** Деплой в основное облако после создания Release Tag.
* **Docs Deployment:** Автоматическая публикация этой документации (Docusaurus) на GitHub Pages.

## 5. Мониторинг релизов
* Ссылки на логи сборки в GitHub Actions.
* Информация об уведомлениях (например, в Telegram) при падении пайплайна.
