## 1. Процесс разработки (Git Flow)
*Описание того, как мы работаем с ветками. Например: запрет пуша напрямую в `main`, использование веток `feature/` для новых задач и `fix/` для исправлений багов.*

## 2. Стандарты именования коммитов
*Правила написания commit messages. Рекомендуется использовать формат **Conventional Commits** (например: `feat: add api for rooms`, `fix: resolve overlap in schedule`).*

## 3. Требования к коду (Code Style)
*Ссылки на используемые линтеры и форматтеры (Prettier для фронтенда, Black или Ruff для Python). Указание, что код должен соответствовать существующему стилю проекта.*

## 4. Создание Pull Request (PR)
*Чек-лист того, что должен сделать автор перед созданием PR:*
* *Код успешно собирается локально.*
* *Добавлены тесты для нового функционала.*
* *Обновлена соответствующая документация (если изменилась логика или API).*

## 5. Процесс Review
*Описание того, кто и как проверяет код. Требование минимум одного аппрува от другого участника команды перед слиянием.*

## 6. Коммуникация
*Куда писать, если возникли вопросы по реализации (ссылки на чат команды или обсуждения в GitHub Issues).*
