Общая архитектура

1. Принципы проектирования​

В основу системы заложены следующие архитектурные принципы:

  • Modularity: Разделение логики на независимые сервисы (генерация, бронирование, уведомления).
  • Scalability: Возможность масштабирования вычислительных узлов для тяжелых алгоритмов генерации расписания.
  • Event-Driven: Использование асинхронных сообщений для минимизации связности (Low Coupling).

2. Диаграмма контейнеров (C4 Model)​

Здесь должна быть размещена диаграмма уровня C2, описывающая основные программные контейнеры (API, Web App, Worker, Database).

3. Описание ключевых компонентов​

3.1. API Gateway​

Единая точка входа для всех запросов. Отвечает за:

  • Маршрутизацию запросов к микросервисам.
  • Аутентификацию и авторизацию пользователей (JWT).
  • Rate limiting для защиты системы от перегрузок.

3.2. Core Service (Ядро системы)​

Центральный сервис, управляющий CRUD-операциями для базовых сущностей:

  • Учебные группы и планы.
  • Реестр преподавателей и аудиторий.
  • Текущее состояние сетки расписания.

3.3. Scheduler Engine (Алгоритмический модуль)​

Изолированный компонент, отвечающий за автоматическое формирование расписания.

  • Вход: Набор ограничений (Constraints) и данных от Core Service.
  • Выход: Оптимизированный проект расписания.
  • Технологии: Специфические библиотеки для решения задач оптимизации (например, OptaPlanner или кастомные эвристические алгоритмы).

3.4. Integration Layer (Слой интеграций)​

Обеспечивает связь с внешними системами университета:

  • Синхронизация данных о студентах/преподавателях.
  • Асинхронный обмен сообщениями через RabbitMQ/Kafka.

4. Потоки данных (Data Flows)​

4.1. Процесс генерации​

  1. Пользователь загружает данные через Web UI.
  2. API Gateway передает задачу в Core Service.
  3. Scheduler Engine получает сигнал к началу расчета, формирует результат и сохраняет его в БД как «черновик».

4.2. Обновление в реальном времени​

Любые изменения (например, бронирование аудитории) публикуются в шину событий, откуда их подхватывают сервисы уведомлений и внешние интеграции.
